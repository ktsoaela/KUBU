JavaScript

JavaScript is optional. Every KUBU component looks and works with scripts off; scripts only make some things smoother.

What works with scripts off

  • Opening and closingDropdowns, accordions, collapse and alerts use <details>. Offcanvas and the CSS modal use :target.
  • ChoosingTabs, rating and the theme switch are radio buttons; the narrow-screen menu is a checkbox.
  • DialogsA button with commandfor opens a <dialog>; form method="dialog" closes it.
  • Validation:user-invalid shows errors after you leave a field, and :has(:invalid) dims the send button.

htmx: one site, real pages

This documentation is a single htmx application built from ordinary pages. Each address is a complete HTML file. With htmx loaded, a click fetches the next page and swaps only the sidebar and article; the header, the theme you picked and the scroll of the menu stay.

Code 
<body hx-boost="true" hx-ext="head-support"
      hx-target="#frame" hx-select="#frame" hx-swap="outerHTML show:window:top"
      hx-push-url="true" hx-select-oob="#site-links" hx-indicator="#site-progress">
  <header class="header">…logo, #site-links, theme switch…</header>
  <div id="frame">
    <nav class="docs-sidebar">…links, one with aria-current="page"…</nav>
    <main id="main" tabindex="-1">…</main>
  </div>
  <footer class="footer">…</footer>
</body>
  • The URL, refresh and back button stay correct. hx-push-url records each page; a refresh loads the real file.
  • The highlight moves. Each response already has aria-current="page" on the right sidebar link, and hx-select-oob swaps the header links too.
  • The title changes. The head-support extension merges the new <title> and description.
  • Feedback is immediate. A progress bar under the header shows while the next page loads.
  • Without htmx every link is a normal navigation to the same page.

The docs script

js/docs.js is about 60 lines. It does not build any part of the page. With it you get:

  1. Your theme choice remembered for the next visit (a few lines of localStorage).
  2. A Copy code button on code samples. The code is always readable in its Code disclosure.
  3. Dialogs opening in browsers that do not support commandfor yet.
  4. Focus moved to the article after htmx swaps a page, so screen readers start at the new content.

The JS layer

An optional set of ES modules in packages/js covers things the browser cannot do alone, like building a card from data or opening an accordion panel from code. Mark an element with data-kubu; the layer sets it up on load and again after every htmx swap (htmx:afterSettle).

Code 
<link rel="stylesheet" href="kubu-framework/dist/kubu.min.css">
<link rel="stylesheet" href="kubu-framework/packages/js/css/main.css">
<script type="module" src="kubu-framework/packages/js/src/main.js"></script>

The second stylesheet holds only the few styles the JS components add, such as tooltip and carousel controls. Leave it and the script out and every component still looks and works the same.
